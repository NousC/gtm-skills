# Sequence framework — the 3-email cadence

Each email is one hypothesis on a different angle. Reply data from one informs the next.

[1] **Email 1 (Day 1)** — pain-led or value-led by signal strength. situation →
    insight → inquisition. 3 lines, under 75 words. no link.
[2] **Email 2 (Day 3-4)** — rotate the angle. if email 1 was pain-led, email 2 goes
    value-led or a different pain. thread or new subject. under 60 words.
[3] **Email 3 (Day 7-8)** — third angle: a brief proof point, a useful resource, or
    a clean breakup. new thread. under 60 words. one link max, only if it earns it.

## Pattern selection

→ signal score 7+ / specific acute pain → **pain-led** (name the pain, show the root cause)
→ strong data, can deliver value before asking → **value-led** (give the finding first)
→ score 3-6 / no sharp behavioral signal → **segment fallback** (the most common
  pain for that profile, stated concretely not generically)

## Tiering (from the Dream 1000 Blueprint)

→ **ICP 85+** → bespoke sequence. fully written from THIS person's post-scan note +
  the company signals. every line specific to them.
→ **ICP 70-85** → one base sequence per signal/angle + per-prospect `{{variables}}`.
  skeleton shared across the segment, values unique per prospect.

## Variables (mid-tier)

→ `{{variable_name}}` syntax, every variable has a fallback value.
→ variables carry data that changes across the segment (the signal hook, a number,
  a quote), not generic personalization. no `{{first_name}}` in the body.
→ if a single email needs more than 3 variables, the targeting is too loose —
  tighten the segment instead.
→ the variable values come straight from the signal's "key data points for copy".
